# 路由与入口决策矩阵

## 先判断权威原稿

| 对象 | 权威原稿位置 | 其他位置的处理 |
|---|---|---|
| 跨团队通用制度或稳定公共资产 | 公共知识库准确目录 | 业务知识库按需放快捷入口 |
| 团队制度、运营流程、会议与通用模板 | 团队运营知识库准确目录 | 相关项目页放入口，不复制正文 |
| POC 模板、过程资料和项目材料 | POC 知识库准确目录 | 数据表原稿仍进入晴天纪数据库 |
| 测试规范、用例、验证材料和质量经验 | 测试知识库准确目录 | 产品或项目页放入口 |
| 产品基线、需求决策、架构和版本资产 | 产品知识库准确目录 | POC、测试或交付页放入口 |
| 正式实施、运维、结项和交付资料 | 正式交付项目知识库准确目录 | 产品或公共库按需放入口 |
| 业务数据表、主数据、表单和强耦合数据资产 | 公共知识库中的晴天纪数据库 | 各业务知识库只放引用、快捷方式、嵌入视图或表单链接 |

## 移动、快捷方式与复制

按顺序判断：

1. 当前节点是否就是唯一权威原稿，且位置正确？是则保留。
2. 当前节点是权威原稿，但位置错误？移动原节点。
3. 当前位置只是业务使用场景？建立指向权威原稿的入口。
4. 目标位置已存在指向同一对象的入口？复用或更新，不重复创建。
5. 只有在法规留档、版本冻结或用户明确要求独立副本时复制，并在标题或正文标注副本性质。

## 完整路径要求

可执行路径必须包含：

```text
知识空间 / 一级目录 / 二级目录或具体项目节点
```

如果实时目录只有一级目录，则以真实存在的最深目录为准。不得虚构二级目录，也不得把节点放在根目录后仅靠标题模拟归属。

## 同名冲突

- 同名且 token 相同：同一对象，跳过创建。
- 同名、token 不同但指向同一权威原稿：保留一个入口，其他标记为重复候选，不擅自删除。
- 同名且内容用途不同：在路由卡中列出差异，使用业务限定词重命名或请求用户确认。
- 同一表单名称出现在不同数据表：以承载表和字段用途为准，不能只凭名称合并。

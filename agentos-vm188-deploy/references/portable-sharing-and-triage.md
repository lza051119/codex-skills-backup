# 跨服务器共享与部署问题闭环

这份参考用于云盘分享的单机部署资料包。它把 VM188 的实践整理成可迁移的工作方法；脚本文件本身仍可能绑定某个 AgentOS 版本、目录布局或历史记录，使用前必须完成目标服务器适配。

## 先判断问题属于哪一类

| 首个真实错误位置 | 记录什么 | 处理位置 | 完成标准 |
| --- | --- | --- | --- |
| 产品代码 | 固定 SHA/tree、镜像 digest、请求/Run、首个真实错误、最小复现 | AgentOSNext 独立工作树 | 私人环境候选回归通过，并提交产品 PR；部署候选和合并版本分开记录 |
| 部署脚本或生成器 | 脚本路径、输入摘要、命令退出码、远端 operation、失败阶段 | 目标服务器对应的桌面 `single-server-deploy/scripts/` | 新 record + 唯一 operation-id 的 dry-run/定向回归通过，README/证据索引和 SHA-256 已更新 |
| 环境或制品 | Worker/Server/Gateway 版本、镜像、API、磁盘、网络、证书、依赖缓存 | 先记录环境 blocker，按部署负责人处理 | 基线重新一致后再判定产品或脚本问题；不要用清库或重试掩盖环境故障 |
| Skill 文档缺口 | 缺少的入口、参数、前置条件、证据或迁移说明 | `SKILL.md` 与 `references/` | 新使用者可以按文档找到只读预检、执行边界和验证证据 |

不要因为页面没有显示、HTTP 200 或 Pod Ready 就跳过后端事实。先看队列/Run、服务日志、数据库和实际对象；把“代码缺陷”“脚本缺陷”“版本混用”“访问阻塞”分开写。

## 在另一台服务器复用资料前

建立新的环境输入和新的 `records/<date>-<sha-or-task>/`，至少替换并核对：

- SSH 主机、hostname、公钥指纹、用户和本机工作目录；
- kubeconfig、context、namespace、应用集群与入口；
- 写锁路径、端口转发、域名/CA 链和证书有效期；
- 产品源码 SHA/tree、镜像来源与 digest、数据库/对象存储/身份组件；
- 目标服务器的磁盘容量、容器运行时、kind/k3s 版本、依赖缓存和网络出口。

第一步只做只读状态、端点和容量预检；第二步固定版本并生成计划；第三步才按四条部署路线选择保留更新、保留升级、业务库重建或应用集群重建。历史 VM188/VM187 的 operation、Pod UID、请求 JSON、证书和账号输入不能直接重放。

## 问题闭环

### 产品代码问题

1. 在稳定基线下保存现象、原生响应、日志片段摘要和最小复现。
2. 确认不是 Worker/Server/Gateway 混版、TLS、网络、存储、权限或依赖缺失。
3. 在产品独立工作树提交最小修复；记录候选 commit/tree 与新镜像 digest。
4. 在已授权的私人环境部署候选，按受影响路径做真实回归。
5. 部署成功后创建/更新产品 PR；PR 合并、候选部署和实机回归分别写证据。

### 部署脚本问题

1. 保留失败脚本、输入 manifest、stdout/stderr、退出码和 operation 状态，不覆盖原记录。
2. 在桌面脚本目录修复；先运行语法/静态检查和只读 dry-run。
3. 用新的 record、唯一 operation-id 和目标锁做最小写入回归，确认失败阶段没有重复副作用。
4. 更新 README、DEPLOYMENT-NOTES、脚本清单和包内 `FILE-MANIFEST.json` / `SHA256SUMS.txt`。

### Skill 缺口

补上“何时使用、哪些输入必须替换、哪些脚本只读、哪些操作需要授权、完成后要保存什么证据”五件事。新增内容要链接到桌面真实入口，不另造一份并行执行器。

## 共享包的分层

- **日常只读入口**：状态、端点、容量、版本和证据索引；可先在其他服务器改参数后使用。
- **受控写入脚本**：构建、导入、初始化、配置、清理和切换；必须先读源码与目标版本，使用新 record/operation/锁。
- **历史诊断与回执**：用于理解已发生的问题和修复依据，不是当前版本的默认命令。

发布时记录每个源文件的原路径、采集时间、大小和 SHA-256，并在上传后重新下载核对。不要上传账号文件、私钥、原始 Secret/DSN、浏览器会话、数据库导出、镜像归档或依赖缓存。

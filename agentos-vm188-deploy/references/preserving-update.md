# VM188 路线一与路线二：保留数据更新

本参考分别说明局部保留更新、全组件保留升级。决定复用基础设施重建业务库时，转入 [路线三](empty-redeploy.md)；决定重建整个应用集群时，转入 [路线四](cluster-rebuild.md)。不把保留数据的前置条件套到已经允许丢弃的数据上。

以桌面 `C:\Users\27616\Desktop\vm188\single-server-deploy\DEPLOYMENT-NOTES.md` 为具体流程。正式 Deploy/CD 不属于本 Skill 的修改或执行范围，旧仓库控制器流程已撤回。

## 路线一：局部保留更新

适用：修复或更新少数组件，能够证明其接口、表结构、身份、信任和 Sandbox 合同与保留组件兼容。数据、集群、入口以及未受影响的组件继续使用。

1. 明确具名更新组件与关联位置。只修 Server 也要检查其初始化容器；修改 Web/BFF 时核对两个入口；修改执行协议时核对 Worker、Gateway、Sandbox 等真实消费者。按依赖确定范围，不能只按改动文件数量选择组件。
2. 固定目标 SHA/tree，检查需要的新配置与原生表结构步骤；列明哪些旧镜像继续使用及其兼容依据。若变更实际要求全套升级，转为路线二的完整执行单。
3. 在桌面准备缺失镜像和本次执行器，按受影响服务的真实停接要求有序替换。保留数据库和对象存储的数据身份，不因更新无状态组件重建数据 Pod。
4. 验证原问题、受影响调用链及旧数据可读，记录实际镜像差异。局部修复通过只能说明这个范围完成，不能写成“整套已升级到最新”。

这一路线在修复范围小、兼容明确时通常最快；它仍可能包含有限的表结构升级，不能将“局部”解释为可以跳过初始化检查。

## 路线二：全组件保留升级

适用：用户需要保留现有会话、项目、文件、身份或模型等配置，并希望整套应用到达选定目标版本。复用基础设施和业务数据，执行必要的表结构与配置升级。

1. 枚举完整目标范围：应用主容器、初始化容器、两个 BFF、Sandbox 模板/attestor、后台 Job 及其运行输入。核对现状到目标的源码、协议、配置和实际数据库结构差异；私有补丁的迁移编号可能与正式序列同号异义，不能只比较 schema version 数字。
2. 为需要转换的结构明确执行顺序、旧新兼容条件和失败后的恢复方式。保留升级涉及数据库变更时，仅换回旧镜像不一定可回退；没有验证过的转换不能靠改版本号、跳过步骤或重打镜像标签完成。
3. 准备完整目标制品，保留准确可复用的镜像和缓存；先落实停接与活动任务处理，再按原生合同更新表结构、运行配置与服务。全组件覆盖不要求把无需变化的第三方基础设施冷重建。
4. 逐项读回最终版本和配置，验证保留数据、真实登录、模型调用、文件、Shell/Resource/Sandbox 及本次业务旅程。完整范围未覆盖时列出缺项，不能用部分服务 Ready 代替整套升级完成。

若保留转换成本过高，应向用户说明发现的具体差异；已有本任务清空授权时可选择路线三，不在未获数据丢弃授权时自行删库。

## 两条保留路线的共同要求

固定一次精确 dev SHA/tree，读取应用代码与迁移边界，核对部署单元和域名 BFF 的实际镜像来源。复用已验证源码、镜像和缓存；只为缺失制品构建，不重打标签伪造来源。

先保存数据 Pod UID/container ID、实际 PVC 挂载、原数据 ID 子集、身份和模型配置摘要。PostgreSQL 和 SeaweedFS 的 emptyDir 不能通过换 Pod 保留。没有已验证转换/恢复路径时不做破坏性迁移；失败后按真实已提交阶段和原生幂等合同续接，不盲重放整条链。

源码和普通文件保持运行用户可读，私有记录另设 0700/0600。根盘容量或 API 健康不满足时先定向评估，不全局清理 Docker 或抢占其他人的进程。新脚本与执行单存桌面，不复制正式部署器。

从真实调用方预检管理路径；kubelet Ready 不证明 API Server 到 Worker `/ready`、`/drain` 可达。识别当前 CNI、源 IP 和规则后才设计 VM188 最小规则，不按历史 IP 开放整个网段或跳过 drain。

双根信任先于叶证书切换，并确认现存进程已加载。Secret 已更新不等于进程已重载。两项 AI 消费者可用桌面工具生成同镜像重载计划，检查对象版本、活动执行租约和保留数据身份。其他消费者或正式续签另写桌面独立执行单；重载命令不代表完成证书轮换。

写操作持有运维锁，验证 hostname、kubeconfig、context、namespace，并比较对象原值/版本。先保证迁移与旧新兼容，再有序停接和替换，不对全部 Deployment 无差别 rollout。

完成后分别证明镜像来源、迁移、保留数据、证书、入口、真实对话和用户需要的 Shell/Resource/Sandbox/业务任务。HTTP 200、Pod Ready、普通对话成功都不足以宣布全部完成。更新桌面状态块和证据记录，明确混用版本与未复验路径。
